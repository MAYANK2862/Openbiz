Create a robust, type-safe Express.js REST API in TypeScript using Drizzle ORM and Supabase PostgreSQL for an Udyam Registration application. Follow these strict architectural guidelines:

1. Folder Structure:
   Inside the `src` folder, create these sub-folders:
   - `app` (modules)
   - `constants`
   - `middlewares`
   - `utils`
   - `config`
   - `types`
   - `logger`
   And these two root files:
   - `src/app.ts`: Registers global middlewares (cors, helmet, express.json, cookie-parser, morgan, error handler) and routes.
   - `src/server.ts`: Loads environment variables, connects to Supabase via Postgres client, and starts the Express server listening on PORT 3001.

2. Modular Pattern:
   Create a module under `src/app/registration/` with the following files:
   - `registration.routes.ts`: Maps the POST /api/v1/registrations route.
   - `dto/create-registration.dto.ts`: Zod schema for validating the incoming payload. Exposes TypeScript type inferred from Zod.
   - `registration.controller.ts`: Controls request/response logic using functional programming.
   - `registration.service.ts`: Handles business logic (checking for duplicate Aadhaar, inserting entries).
   - `registration.schema.ts`: Drizzle schema file defining the "udyam_submissions" PostgreSQL table (id, aadhaar_number [unique index], owner_name, declaration, type_of_organisation, pan_number, created_at, updated_at).

3. Core Utilities & Middlewares:
   - Create custom response classes `ApiSuccessResponse` and `ApiErrorResponse` in `src/utils/response.ts` conforming to the response convention:
     Success: { success: true, message: "...", data: {...} }
     Error: { success: false, message: "...", errors?: [...] }
   - Create custom error classes (like `BadRequestError`, `ConflictError`) in `src/utils/errors.ts` and handle them using a global error-handling middleware in `src/middlewares/error.middleware.ts`.
   - Implement a custom `asyncHandler` wrapper in `src/utils/asyncHandler.ts` to capture controller exceptions.
   - Implement a generic `validateRequest` validation middleware in `src/middlewares/validation.middleware.ts` that takes a Zod schema and validates `req.body`.
   - Setup Winston logger in `src/logger/` and use it to log entries, exits, exceptions, and database queries. Never use console.log.
   - Load environment variables securely inside `src/config/env.config.ts` using a single `.env` file configuration.

4. Domain Logic:
   - Post `/api/v1/registrations`: Validates fields:
     * `aadhaar_number`: 12-digit string
     * `owner_name`: Alphabetic name
     * `declaration`: Boolean (must be true)
     * `type_of_organisation`: String
     * `pan_number`: String (Conditional: required only if type_of_organisation is not '1' [Proprietorship], otherwise optional).
   - If validation fails, return 400 with details.
   - If Aadhaar is duplicate, throw a ConflictError (409).
   - If successful, save to Supabase and return 201 with success details.
   - Implement a health check API at "/health" returning status "healthy".
